# 微信公众号历史文章备份工具 v1.2.0

本次更新修复列表来源识别：自动选择已登录的发表记录标签页，从浏览器打开时就监听列表响应，并支持 `wx.cgiData` 等页面内置列表数据。后台以 HTML 直接返回文章列表时，按页面地址逐页读取。采集目录中新增不含 Cookie、token 值的「采集诊断.json」。

v1.0.2 进一步适配自有公众号后台的 `appmsg_info/content_url` 字段，包括独立发表记录的同级文章详情、多图文、布尔删除标记和只提供日期的记录。若所有记录都无法解析出文章详情，不会再将目录标记为完整。

## Windows 运行

本交付包含 Python 源代码和已打包的 64 位 Windows 程序。已安装 Microsoft Edge 的 Windows 10/11 可直接双击「启动备份.cmd」，不需要安装 Python。请保留运行目录中的 `_internal` 文件夹，不能只复制 EXE。

1. 点击「① 打开登录浏览器」。这是程序独立的 Edge 配置，不连接你原来打开的普通浏览器。
2. 自己扫码登录，进入「内容管理 → 发表记录」，清空搜索和日期筛选。程序会尝试点击这些菜单；菜单变化时可手动进入。
3. 选择备份目录，点击「② 获取全部文章列表」。界面按发表记录显示进度；后台是多少页就采集多少页，不将页数硬编码为 10。
4. 核对界面显示的已采集发表次数与后台一致。例如 95 次发表可包含超过 95 篇文章。只有总数、分页和重复检查通过，才允许批量下载。
5. 选择 HTML、PDF 或两者，点击「③ 开始 / 重试失败项」。建议先用同一份目录试存，并检查首篇排版；可以随时暂停或停止。
6. 暂停后点击「继续」；停止或重启后再点「开始」，已成功文件按 SHA-256 校验后跳过。损坏文件、缺少格式和失败项会重新处理。

操作系统将新窗口放在后台时，可从任务栏选择“微信公众号历史文章备份”。程序仅允许同一项目运行一个窗口。关闭登录 Edge 不会退出主窗口；可以重新点击打开登录浏览器。

## 保存结果

默认保存在项目文件夹内的「备份」：

```text
备份/
  catalog.json                 当前列表、各格式校验值和进度
  下载续传索引.json             重新采集列表时保留已有下载状态
  文章目录.xlsx                全部记录，包含完整标题、发表时间、链接、路径、状态
  备份统计.txt / .json         发表次数、文章记录数、下载情况与采集错误
  异常记录.json                删除、缺链接、缺图、非图文等需核对的记录
  采集证据/page_001.json       后台原始列表响应（不保存请求 URL、token 或 Cookie）
  2025-01-01/标题_唯一ID/
    article.html
    article.pdf
```

HTML 将图片与 CSS 背景图直接嵌入文件，无需依赖微信图片服务器，也无需额外的图片文件夹。正文中的普通超链接仍用于联网访问；离线预览和 PDF 渲染不需要访问这些链接。使用 CSP 禁止脚本和远程资源加载。

PDF 使用 Edge 的打印引擎，优先保留文字颜色、字号、表格和背景色。HTML 保存正文实际计算样式；目标电脑缺少的字体会使用本机备用字体。A4 分页与手机原版长页面会有差异。动态交互、伪元素、视频、音频、小程序、直播、外部嵌入内容不能保证还原；已识别的媒体内容会提示人工核对，PDF 中动态图像一般只保留静态画面。

## 可靠性和核对

- 采集实际后台发出的 `appmsgpublish` 列表请求，通过登录浏览器的同一会话读取分页，不需要输入密码或复制 Cookie。
- 按发表组逐页遍历，拆开多图文，按文章标识去重。重复页、提前空页、总数变化、未知结构均停止并标记未完成；不会把局部结果报告为完整备份。
- 采集结束再次核对第一页。采集期间请勿发表、删除或修改历史记录。接口本身没有快照隔离，仍建议最终与后台人工抽查。
- 优先使用发表时间或发送时间。缺少发表时间时明确留空并提示核对，不拿素材创建时间冒充发表时间。
- 后台标记的删除记录会保留。删除文章、违规不可访问正文和无链接记录不能从后台恢复；保留已知标题和时间供核对。若后台已清空多图文详情，程序无法推断原来的篇数。
- 列表请求最多四次尝试，限流时等待 20 秒；文章最多三次尝试，单张图片最多三次尝试。串行处理并留间隔。
- 暂停、停止在当前网络请求结束后生效；单次网络请求最长约 45 秒。强制关机后，重新开始会修复未完成文件。不能从某张图片的字节偏移恢复，但不会重下已完成且校验通过的整篇文章。
- 图片下载失败会保存可读的部分结果并记入警告，状态为“部分完成”；不会当作完全成功。再次开始会尝试重存这些文章。
- 运行期间请不要用 Excel 占用「文章目录.xlsx」。即使 Excel 导出受阻，`catalog.json` 中的进度仍保留，关闭 Excel 后点击「导出目录与报告」。
- 不同公众号建议使用不同下载目录，并关闭程序后使用不同项目副本登录；不要在一次采集期间切换账号。

## 开发与测试

源码入口 `main.py`，核心模块在 `wxbackup/`。推荐 64 位 Python 3.11/3.12，依赖锁定在 `requirements.txt`。`setup.cmd` 创建项目专用 `.venv` 并安装依赖；源码运行：

```powershell
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest tests -q
```

测试运行依赖本机 Edge。本地 HTTP 服务和模拟后台响应测试 95 次发表、10 页、190 篇多图文、删除、重复页、请求失败与恢复；真实 Edge 测试列表响应捕获、HTTP 分页、图片和背景图内嵌、断网 HTML、PDF、Excel 公式注入防护和损坏文件修复。不将这些测试称为真实账号验收。

`build.cmd` 使用 PyInstaller 生成目录版程序。完整目录复制到 `runtime` 后由启动脚本运行。发布前可执行 `WechatBackup.exe --smoke-test <测试目录>`，检查 GUI、暂停/继续、Edge PDF 和 Excel 导出。测试输出只应放入独立目录。

## 隐私与会话

浏览器登录状态位于 `data/browser`，配置与本地运行日志位于 `data/`。该目录含登录会话，不要分享或上传；源代码、测试和安装程序不需要这些登录数据。程序只读取你的公众号后台并写入本地，不执行发表、删除或修改后台记录。验证页面由你自己完成；不会自动绕过微信验证。
